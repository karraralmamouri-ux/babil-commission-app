# حالة المشروع

آخر تحديث: 2026-08-04

خط الأساس: `05e51c631cef29ad93f8072c1221fc9493f5c24f`

مرحلة العمل: تثبيت قابلية الاستعادة واختبارات Staging

فرع العمل الحالي: `feat/supabase-restorable-baseline`

## الحالة الفعلية

- المستودع يحتوي على `index.html` فقط في خط الأساس.
- الملف يجمع HTML وCSS وJavaScript وبيانات ابتدائية في نحو 780 سطراً و62,841 بايت.
- GitHub Pages يعرض الصفحة بنجاح.
- المصادقة تتصل بـSupabase عبر عميل REST خفيف داخل الملف.
- ملف المستخدم يقرأ من `profiles`.
- إدارة المستخدمين تستدعي Edge Function باسم `admin-users`؛ استُرجع مصدرها ومصدر `admin-create-user` من لوحة Supabase إلى المستودع.
- بيانات العمولات والأرشيف وسجل التدقيق تحفظ في `localStorage` تحت مفاتيح منها `babil_commission_v2`.
- يوجد baseline معاد البناء ومهاجرة أمنية forward-only ومصادر Edge Functions؛ أُعيد بناء Staging منهما، وأضيف CI لتشغيل الاختبارات على Pull Requests و`main`.
- يوجد فرع بعيد واحد `main`، وهو غير محمي، ولا توجد tags.

## ما يعمل وفق قراءة الكود

- تسجيل الدخول والخروج عند توفر Supabase والحسابات الصحيحة.
- قراءة دور المستخدم وتقييد عناصر الواجهة.
- حساب الكميات والاستحقاق والمتبقي وحالة الصرف.
- البحث والتصفية ولوحات الملخص.
- إضافة الوكلاء وتعديلهم وحذفهم محلياً حسب الدور.
- الأرشيف الشهري المحلي والتصدير إلى CSV.
- استيراد CSV الأساسي.

## ما هو معطل أو غير موثوق

- كان ملف مكتبة Excel المنشور يرجع HTTP 404؛ عولج بنسخة SheetJS مثبتة واختبار round-trip، وتحقق نجاحه في GitHub Pages بعد دمج PR #3.
- البيانات ليست مشتركة بين الأجهزة أو المتصفحات.
- سجل التدقيق محلي وقابل للتغيير أو المسح.
- الحفظ المؤجل يعرض التعديلات للفقد قبل «حفظ الشهر».
- صلاحيات البيانات المالية ليست محمية خادمياً لأن البيانات محلية.
- مقارنة الوكيل تعتمد على الاسم، وترتيب بعض الأشهر نصي.
- الشهر الجديد يعتمد على تاريخ الجهاز لا الشهر المفتوح.
- لا يملك الإنتاج سجلاً تاريخياً في `supabase_migrations`، لكن baseline المعاد البناء وسجل Staging المثبت يجعلان مخطط التطبيق قابلاً لإعادة الإنشاء على بيئة فارغة.
- الخطة المجانية لا توفر scheduled database backups.
- كانت سياسة `profiles_update` تسمح للمستخدم بتحديث صفه مع `UPDATE` على كل الأعمدة؛ أُغلق المسار في الإنتاج بالمهاجرة `20260804183000_harden_authorization.sql` وتحقق منع التعديل بمحاكاة دوري admin وaccountant.
- جدولَا audit المركزيان فارغان، ويوجد نموذجان متداخلان للعمولات والتدقيق.

## ما أُنجز في هذه المرحلة

- إنشاء وثائق المشروع الدائمة وقواعد العمل والمساهمة.
- توثيق خط الأساس والمخاطر والبنية الحالية والمستهدفة.
- إضافة خطة قاعدة البيانات والأمان والاختبار والتشغيل وخارطة الطريق.
- لم يتغير سلوك `index.html`.
- إضافة harness معزول يقرأ JavaScript الفعلي من `index.html` دون شبكة.
- تثبيت اختبارات حدود الشرائح والحساب والدفع والحالة والشهر وCSV وتطبيع الاستيراد.
- تسجيل عيبَي الانتقال السنوي وإنشاء الشهر كاختبارات TODO قبل الإصلاح.

## التحقق الحالي

- فحص Git: شجرة `main` الأصلية نظيفة ومطابقة لـ`origin/main` قبل إنشاء فرع العمل.
- فحص النشر: الصفحة الرئيسية ترجع HTTP 200 وحجمها يطابق الملف.
- فحص Excel: المورد المشار إليه يرجع HTTP 404.
- فحص Supabase العام: إعدادات Auth ترجع HTTP 200 بالمفتاح المنشور، واستعلام مجهول محدود إلى `profiles` لم يكشف صفوفاً (`Content-Range: */0`)، بينما مخطط REST العام يرجع HTTP 401.
- فحص ساكن: تمت قراءة كامل `index.html` ووظائفه ومسارات التخزين والاتصال.
- اكتمل اختبار سياسات RLS بمحاكاة JWT لدوري admin وaccountant داخل transaction مع `ROLLBACK`: المحاسب يرى profile الخاص به فقط ولا يملك UPDATE، والمدير يرى profile كليهما ولا يملك UPDATE المباشر.
- `npm test`: نجح 25 اختباراً دون فشل أو TODO، وتشمل قواعد العمولة وExcel وانتقالات الأشهر والنسخة الاحتياطية وضوابط Supabase والـbaseline والقيود المالية.
- إصلاح Excel: SheetJS CE 0.20.3 محلي، وتحقق الاختبار من الإصدار وقراءة/كتابة ملف XLSX في الذاكرة.
- اختبار تقديم محلي عبر مسار فرعي يحاكي GitHub Pages: الصفحة وملف SheetJS يرجعان HTTP 200.
- تحقق النشر الإنتاجي على commit `33fa300`: الصفحة وملف SheetJS يرجعان HTTP 200، والمسار القديم 404، وبصمة الملف المنشور تطابق المصدر المراجع.
- إصلاح انتقالات الأشهر: ترتيب زمني موحد، مقارنة بآخر فترة مؤرشفة سابقة، وإنشاء الشهر من الفترة المفتوحة؛ تحقق نشره على commit `11ee327`.
- تحقق GitHub Pages لإصلاح الأشهر: workflow ناجح، الصفحة HTTP 200، والدوال الجديدة موجودة بينما منطق تاريخ الجهاز القديم غير موجود.
- أضيفت أداة نسخ احتياطي محلية إصدار 1 للمدير فقط، تحفظ الحالة التشغيلية مع SHA-256 وتستبعد بيانات جلسة Supabase؛ الاستيراد منها غير مسموح بعد.
- تحقق نشر النسخة الاحتياطية على commit `43adaa1`: workflow ناجح، صفحة الإنتاج HTTP 200، وزر المدير وصيغة الإصدار 1 وبصمة SHA-256 موجودة في المورد المنشور.
- تدقيق Supabase المصادق: 2 مستخدمين و2 profiles نشطين (`admin` و`accountant`)، فترتان، 82 `commission_rows`، و0 سجلات في جدولي audit.
- جميع جداول `public` تستخدم RLS، لكن ثبت مسار تصعيد role عبر profile الذاتي ومنح UPDATE؛ أعدت مهاجرة تقفل المسار وتقلص grants.

## الحالة الفعلية

- المستودع يحتوي على `index.html` فقط في خط الأساس.
- الملف يجمع HTML وCSS وJavaScript وبيانات ابتدائية في نحو 780 سطراً و62,841 بايت.
- GitHub Pages يعرض الصفحة بنجاح.
- المصادقة تتصل بـSupabase عبر عميل REST خفيف داخل الملف.
- ملف المستخدم يقرأ من `profiles`.
- إدارة المستخدمين تستدعي Edge Function باسم `admin-users`، لكن مصدر الدالة غير موجود في المستودع.
- بيانات العمولات والأرشيف وسجل التدقيق تحفظ في `localStorage` تحت مفاتيح منها `babil_commission_v2`.
- لا توجد migrations أو سياسات RLS أو اختبارات أو build أو CI مخصص داخل المستودع.
- يوجد فرع بعيد واحد `main`، وهو غير محمي، ولا توجد tags.

## ما يعمل وفق قراءة الكود

- تسجيل الدخول والخروج عند توفر Supabase والحسابات الصحيحة.
- قراءة دور المستخدم وتقييد عناصر الواجهة.
- حساب الكميات والاستحقاق والمتبقي وحالة الصرف.
- البحث والتصفية ولوحات الملخص.
- إضافة الوكلاء وتعديلهم وحذفهم محلياً حسب الدور.
- الأرشيف الشهري المحلي والتصدير إلى CSV.
- استيراد CSV الأساسي.

## ما هو معطل أو غير موثوق

- ملف مكتبة Excel المنشور يرجع HTTP 404؛ استيراد XLSX غير قابل للاعتماد.
- البيانات ليست مشتركة بين الأجهزة أو المتصفحات.
- سجل التدقيق محلي وقابل للتغيير أو المسح.
- الحفظ المؤجل يعرض التعديلات للفقد قبل «حفظ الشهر».
- صلاحيات البيانات المالية ليست محمية خادمياً لأن البيانات محلية.
- مقارنة الوكيل تعتمد على الاسم، وترتيب بعض الأشهر نصي.
- الشهر الجديد يعتمد على تاريخ الجهاز لا الشهر المفتوح.
- إعداد Supabase وRLS وEdge Function غير قابل لإعادة الإنشاء من المستودع.

## ما أُنجز في هذه المرحلة

- إنشاء وثائق المشروع الدائمة وقواعد العمل والمساهمة.
- توثيق خط الأساس والمخاطر والبنية الحالية والمستهدفة.
- إضافة خطة قاعدة البيانات والأمان والاختبار والتشغيل وخارطة الطريق.
- لم يتغير سلوك `index.html`.

## التحقق الحالي

- فحص Git: شجرة `main` الأصلية نظيفة ومطابقة لـ`origin/main` قبل إنشاء فرع العمل.
- فحص النشر: الصفحة الرئيسية ترجع HTTP 200 وحجمها يطابق الملف.
- فحص Excel: المورد المشار إليه يرجع HTTP 404.
- فحص ساكن: تمت قراءة كامل `index.html` ووظائفه ومسارات التخزين والاتصال.
- لم تُنفذ اختبارات تسجيل دخول أو RLS لعدم توفر وصول Supabase وحسابات اختبار.

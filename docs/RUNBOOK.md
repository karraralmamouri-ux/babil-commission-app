# دليل التشغيل

## فحص سريع للحالة الحالية

1. تحقق من أن GitHub Pages يعرض `index.html`.
2. تحقق من تسجيل الدخول بحساب اختبار.
3. لا تدخل بيانات إنتاجية لأغراض الاختبار.
4. صدّر CSV قبل أي عملية قد تستبدل البيانات المحلية.

## النشر الحالي

- المصدر: فرع `main`.
- المستضيف: GitHub Pages.
- لا يوجد build مخصص في خط الأساس.
- بعد أي نشر، افحص HTTP 200، شاشة الدخول، RTL، Console، ومسارات الموارد.

## النسخ الاحتياطي الانتقالي لـlocalStorage

قبل الترحيل يجب استخدام أداة تصدير معتمدة تحفظ JSON الأصلي وchecksum وبيانات المصدر: الجهاز، المتصفح، المستخدم والتوقيت. لا تنسخ بيانات تشغيلية إلى Git أو قنوات غير آمنة.

## الاسترجاع المستهدف

1. تحديد آخر نسخة سليمة ووقت الحادث.
2. إيقاف الكتابة إن كان استمرارها يزيد الضرر.
3. استرجاع إلى بيئة منفصلة أولاً.
4. مقارنة أعداد الوكلاء والكميات والمستحق والمدفوع والمتبقي لكل شهر.
5. اعتماد مسؤول العمل قبل تبديل الإنتاج.
6. توثيق الحادث والسبب والإجراء الوقائي.

## فشل النشر

- لا تعدل `main` بسرعة دون معرفة السبب.
- راجع commit وGitHub Pages job والموارد المفقودة.
- ارجع إلى آخر commit معروف عبر revert قابل للتدقيق، لا بإعادة كتابة التاريخ.
- تحقق أن قاعدة البيانات لم تتغير مع نشر الواجهة قبل الرجوع.

## فشل Supabase أو الشبكة

- اعرض الواجهة بوضع آمن ولا توهم المستخدم بأن الكتابة نجحت.
- لا تكرر دفعة دون idempotency key.
- احتفظ بالإدخال المؤقت غير الحساس فقط وفق تصميم معتمد.
- راجع logs وrequest ID قبل إعادة العملية.

## معلومات الوصول المطلوبة لاحقاً

- مالك GitHub وإعدادات Pages وbranch protection.
- مسؤول Supabase وبيئة Staging.
- حسابات اختبار للأدوار الأربعة.
- مسؤول اعتماد المجاميع المالية والترحيل.

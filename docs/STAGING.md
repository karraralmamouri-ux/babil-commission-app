## اختبار النسخ والاسترجاع

- الملف المحلي المستبعد من Git: `backups/staging-public-2026-08-04.dump`.
- الحجم: 39,508 بايت.
- SHA-256: `ce5ad1d07840f690e927ff4b765874a172c85c8f25c97b59eca5caae8cd0a46f`.
- يحتوي 103 TOC entries وستة TABLE DATA entries على الأقل.

اختبار `pg_restore --clean --if-exists --no-owner --exit-on-error` أظهر أن Supabase يمنع تغيير `DEFAULT ACL` المملوكة للدور الداخلي `supabase_admin`. أُعيد الاختبار بقائمة restore تستبعد 6 عناصر `DEFAULT ACL` فقط وتبقي ACL الجداول والدوال والسياسات؛ نجح استرجاع 105 عناصر، ثم نجحت اختبارات Auth/RLS الـ48 كاملة.

هذه النسخة تحتوي حسابات وبيانات Staging التجريبية فقط، ولا تحتوي كلمات مرور الاختبار. تبقى مع ذلك مقيدة الوصول لأنها تتضمن profiles التجريبية.

## اختبار الصلاحيات

الأمر `npm run test:staging` يشغّل `scripts/verify-supabase-staging.mjs`. يتوقف السكربت ما لم:

- يكون `ALLOW_STAGING_TESTS=true`.
- يطابق `SUPABASE_URL` مرجع Staging حرفياً.
- يختلف مرجع Staging عن مرجع الإنتاج.
- يتوفر ملف الحسابات المحلي والأدوار الأربعة.

الاختبار الأساسي نجح في 48 تحققاً، ثم توسع بعد مهاجرة RPC إلى 56 تحققاً شملت:

- تسجيل دخول الأدوار الأربعة.
- رؤية المدير لكل profiles ورؤية بقية المستخدمين لصفهم فقط.
- منع تعديل profile وتصعيد الدور مباشرة.
- صحة `current_app_role()` لكل دور.
- سماح إنشاء الشهر والصف للمدير فقط.
- سماح المحاسب بتعديل بيانات الصرف ومنعه من تغيير الكميات أو إنشاء صفوف.
- منع `monitor` و`viewer` من الكتابة.
- رفض قاعدة البيانات للكميات والمدفوعات السالبة.
- نجاح `admin-users` للمدير ورفض المحاسب بحالة HTTP 403.
- حذف fixture المالي المؤقت في نهاية الاختبار حتى عند الفشل.
- رفض الكتابة المالية المباشرة لكل جلسات المتصفح.
- نجاح `record_commission_payment` للمدير/المحاسب ورفض المتابع والمشاهد، مع حساب المستحق خادمياً ومنع تجاوزه.
- نجاح `update_commission_row` للمدير فقط، ورفض التعارض القديم ومنع خفض المستحق دون المبلغ المصروف.
- replay لنفس `request_id` لا ينشئ عملية أو سجل audit ثانياً.

## قواعد التشغيل

1. اربط CLI بـStaging فقط وتحقق من project ref قبل `db push` أو `db reset`.
2. نفّذ `db push --dry-run` قبل التطبيق.
3. لا تستخدم حسابات أو بيانات إنتاج لأغراض الاختبار.
4. شغّل الاختبارات المحلية ثم اختبار Staging بعد كل migration أو تغيير Edge Function.
5. عند الاسترجاع من dump، أنشئ قائمة بـ`pg_restore --list` واستبعد عناصر `DEFAULT ACL` الداخلية فقط؛ لا تستخدم `--no-acl` لأنه يسقط منح الجداول المطلوبة.
6. لا تطبق baseline المعاد بناؤه على الإنتاج؛ يحتوي حارساً يرفض schema غير الفارغ.
7. احذف Access Token المؤقت بعد اكتمال العمل وتحقق من صفحة الرموز.

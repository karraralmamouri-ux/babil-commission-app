# خارطة الطريق

الانتقال بين المراحل يعتمد على بوابات قبول، لا على التاريخ وحده.

## M0 — Preservation and access

- نسخة Git كاملة وحالة موثقة.
- وصول قراءة إلى Supabase.
- جرد أجهزة ومتصفحات الإنتاج.
- تصدير وchecksum لنسخ `localStorage`.

**البوابة:** كل مصدر بيانات معروف قابل للاسترجاع.

## M1 — Project foundation

- الذاكرة الدائمة، خط الأساس، المخاطر وخطط التشغيل والاختبار.
- قواعد الفروع والـPR والتسليم.

**البوابة:** يستطيع مساهم جديد فهم الحالة والخطوة التالية.

## M2 — Characterization and urgent fixes

- اختبارات قواعد العمولة وحدود الشرائح.
- اختبارات الأشهر وCSV.
- إصلاح XLSX في تغيير مستقل.
- توثيق النتائج الحالية للمقارنة.

**البوابة:** الحسابات قابلة للتكرار وExcel/CSV مختبران.

## M3 — Incremental modularization

- استخراج CSS وJavaScript إلى وحدات.
- فصل domain عن DOM والشبكة.
- Vite/TypeScript وCI ونشر GitHub Pages قابل للتكرار.

**البوابة:** لا تغيير غير مقصود في السلوك أو العرض.

## M4 — Supabase staging foundation

- فحص المخطط الحالي.
- migrations، constraints، RLS، seed غير حقيقي، واختبارات الأدوار.
- نقل مصدر `admin-users` إلى Git ومراجعته.

**البوابة:** إعادة إنشاء Staging واختبارات RLS ناجحة.

## M5 — Safe migration tooling

- export، preview، conflict detection، idempotent import، reconciliation، rollback.
- تجربة بيانات منزوعة الحساسية ثم نسخة تشغيلية مصرح بها.

**البوابة:** تطابق أعداد ومجاميع كل شهر دون حذف الأصل.

## M6 — Centralized pilot

- تشغيل مستخدمين مختارين على Staging/Production pilot.
- دفع مركزي وتدقيق ومراقبة الأخطاء.
- فترة قراءة للنسخة المحلية وخطة رجوع.

**البوابة:** دورة شهر كاملة ومطابقة مالية معتمدة.

## M7 — Production v1.0

- Supabase المصدر الوحيد.
- دورة اعتماد وقفل الشهر.
- نسخ احتياطية واختبار استرجاع ومراقبة وتشغيل موثق.

## لاحقاً

- تحسينات UX وتقارير ورسوم بعد استقرار المصدر المركزي.
- تقييم framework UI عند وجود حاجة مثبتة.

# تدقيق خط الأساس

تاريخ الفحص: 2026-08-04

Commit: `05e51c631cef29ad93f8072c1221fc9493f5c24f`

## النطاق

فحص ملفات المستودع، تاريخ Git، `index.html`، النشر، المصادقة، الأدوار، الحسابات، التخزين، الأشهر، المستخدمين، والاستيراد والتصدير. الفحص لا يشمل داخل مشروع Supabase لعدم توفر وصول إداري أو حسابات اختبار.

## المستودع والنشر

- ملف متعقب واحد: `index.html`.
- فرع بعيد واحد: `main`، غير محمي.
- لا tags ولا releases.
- رسائل commits السابقة عامة في معظمها مثل `Update index.html`؛ لا يعاد كتابة التاريخ.
- GitHub Pages نشط ويعرض الملف مباشرة.
- لا يوجد workflow مخصص أو فحص تلقائي داخل المستودع.

## الواجهة والمنطق

- صفحة RTL واحدة تشمل شاشة الدخول، الملخصات، إعدادات الأسعار، جدولَي المناطق، سجل التدقيق وإدارة المستخدمين.
- CSS مضمّن، responsive أساسي عند 1100px و720px.
- JavaScript عالمي مع inline event handlers وDOM مبني بكثافة عبر `innerHTML`.
- قواعد الحساب مختلطة بحالة الواجهة، ما يصعب اختبارها مستقلة.

## البيانات والحفظ

- الحالة تشمل الشهر، بيانات المنطقتين، الشرائح، الأرشيف، وسجل التدقيق.
- التعديلات العادية تستدعي `save()` الذي يعلّمها غير محفوظة فقط؛ الكتابة الفعلية تحتاج `save(true)` عند حفظ الشهر.
- البيانات الحالية ليست متزامنة ولا مركزية.
- `Infinity` في آخر شريحة لا يحتفظ بقيمته عند JSON serialization، ويحتاج تمثيلاً صريحاً في التصميم الجديد.

## المصادقة والصلاحيات

- يوجد عميل REST مخصص لـSupabase ومفتاح Publishable في الواجهة.
- الجلسة تخزن في `localStorage`، ولا يظهر تنفيذ refresh متكامل للتوكن.
- الدور يقرأ دورياً من `profiles`، وتستخدم `ensurePermission` قبل تعديلات الواجهة.
- هذه الحواجز مناسبة للواجهة فقط؛ لا تثبت وجود RLS أو أمان خلفي.
- `verifyCurrentUser` يبقي الواجهة عند خطأ الشبكة، بينما عمليات التعديل تفشل بشكل محافظ عبر `ensurePermission`.

## الأشهر والحسابات

- الشرائح الحالية: T1 حتى 200، T2 من 201 إلى 400، وT3 من 401 فما فوق.
- المستحق = مجموع كمية كل باقة مضروباً في سعرها ضمن الشريحة المختارة.
- المدفوع يقيّد في الواجهة بين صفر والمستحق.
- اختيار الشهر السابق وترتيب مفاتيح `MM/YYYY` يحتاجان توحيداً زمنياً.
- تعريف الوكيل بالاسم يجعل إعادة التسمية تكسر المقارنة التاريخية.

## الاستيراد والتصدير

- CSV parser مخصص ويدعم الاقتباس الأساسي، لكنه يحتاج اختبارات للسطور متعددة الأسطر والترميزات والتكرار.
- XLSX يعتمد على ملف غير موجود؛ المورد المنشور يرجع 404.
- الاستيراد يستبدل مجموعة البيانات الحالية بعد تأكيد واحد ولا يقدم dry-run أو تقرير تعارض أو rollback دائم.
- التصدير CSV يضيف BOM مناسباً لـExcel ويشمل الحقول المالية الأساسية.

## أولويات المعالجة

1. نسخ بيانات المتصفحات وجرد مصادر الحقيقة.
2. توثيق Supabase ونسخ Edge Function والمigrations إلى Git.
3. اختبارات الحساب وخط أساس قابل للمقارنة.
4. إصلاح Excel دون تغيير تنسيق البيانات.
5. تقسيم الكود تدريجياً.
6. تصميم Supabase وRLS في Staging.
7. أداة ترحيل idempotent مع reconciliation.
8. التحويل المركزي والإغلاق المالي والتدقيق.

# مطابقة النسخ المحلية مع التصدير المركزي

هذه العملية للقراءة فقط. هدفها إثبات ما إذا كانت نسخة `localStorage` تطابق تصديراً موثوقاً من جدولي `commission_months` و`commission_rows` قبل بناء أي استيراد أو تفعيل الكتابة المركزية.

## المدخلات

- ملف نسخة JSON صالح من زر «نسخة احتياطية JSON».
- مجلد تصدير مركزي يحتوي `commission_months.json` و`commission_rows.json`.
- تبقى الملفات التشغيلية داخل مساحة مقيدة ومستبعدة من Git.

## التشغيل

```powershell
npm run reconcile:backup -- "C:\المسار\backup.json" "C:\المسار\central-export"
```

الأداة تتحقق من بصمة النسخة، وتطابق الفترة والشرائح وهوية الصف الداخلية والكميات والمدفوعات وتاريخ الصرف. التقرير لا يطبع أسماء الوكلاء؛ يعرض أعداد الفروقات والمجاميع فقط.

## تفسير النتائج

- `sameMonthReconciled=true`: كل فترة محلية موجودة مركزياً بالمفتاح والمحتوى نفسيهما.
- `everyLocalContentExistsCentrally=true`: المحتوى موجود مركزياً، وقد يكون محفوظاً تحت مفتاح شهر مختلف؛ هذا لا يجيز إعادة التسمية تلقائياً.
- `duplicateCentralContent`: فترات مركزية مختلفة ذات محتوى متطابق تماماً وتحتاج مراجعة مصدرها.
- `closestCentralComparisons`: مقارنة آمنة للفترات غير المتطابقة، تتضمن عدد الصفوف والحقول المختلفة دون كشف الهوية.
- `safeToAutoImport` يبقى `false` عمداً. الأداة لا تكتب إلى Supabase ولا تعتمد مصدراً تلقائياً.

## بوابة القبول

لا يبدأ الاستيراد أو ربط الكتابة إلا بعد:

1. توثيق كل نسخة تشغيلية مع الجهاز والمتصفح ووقت التصدير.
2. تفسير اختلاف مفاتيح الأشهر والمجاميع والشرائح.
3. اعتماد مصدر كل فترة دون حذف أي نسخة أصلية.
4. أخذ نسخة قاعدة بيانات قابلة للاسترجاع وتجربة الاستيراد على Staging.
5. مطابقة ما بعد الاستيراد وإثبات idempotency وخطة الرجوع.
